# Scientific asset and virtual lab services

## Implemented foundation

The platform now has a shared `scientific_assets` MySQL registry, an authenticated API mounted at `/api/science/assets`, an asset library at `/scientific-assets.html`, and a reusable viewer at `/scientific-viewer.html?asset=<asset-key>`. The additive migration is `npm run migrate:scientific-assets`; it creates the table, adds the `import_status` field to existing installations, and idempotently registers the sourced examples for the six labs. Apply it to the configured CBT database before using the registry. The migration does not alter existing LMS or CBT rows or download third-party assets.

Registry records retain subject/category, classification, model format and URL, local/remote storage reference, institution and source record, author, license and attribution, references, dimensions/units, component and label definitions, supported interactions, import state, acquisition/verification dates, review state, visibility, and creator. Import state distinguishes `candidate`, `source_connected`, `imported_local`, and `external_reference`. Tutors can submit draft records; authenticated admins can mark source review or platform scientific review. Students only receive records explicitly published in a reviewed state. There is no generic file upload path. Candidate files must be authorized and checked before any download or re-hosting.

Each lab page has a **Sourced assets** panel. It reads permitted records from the registry, displays source/license/import metadata, opens model and image records in the shared viewer, and directs data references to their source. The Mathematics CO₂ and Geography terrain entries can invoke their existing graph-load and real-elevation controls. Classroom lesson cards link to the class-subject asset library; tutors can insert permitted model/image references into the existing classroom whiteboard. Data-only references are omitted from the 3D whiteboard picker. See the [full inventory](./SCIENTIFIC_ASSET_INVENTORY.md) for individual licenses, download states, interactions, and validation status.

The student portal groups the six subject and graphing workbenches into a dedicated Learning Labs directory. Lab headers and workspaces adapt to narrower screens, while the scientific asset library presents searchable provenance, license, review, and viewer actions in responsive cards with explicit loading, empty, and error states.

## Viewer formats and behavior

The Three.js viewer supports GLB/glTF, OBJ, STL, PDB, SDF/MOL, and image planes for PNG/JPG/JPEG/SVG. It provides OrbitControls rotation, zoom and pan, camera reset, fullscreen, mesh/atom selection, hide/isolate/restore, and a selected-atom leader label. Image planes are flat static images: rotating or zooming the plane does not make the depicted parts independently interactive. PDB chain/residue and atom labels come from coordinate records. PDB files without explicit CONECT records use distance-inferred covalent links; the viewer identifies that approximation. PubChem SDF bonds are read from the source bond records. Sphere sizes and bond widths are visual aids, not scale-accurate atom dimensions. Capped cross-sections, interactive part explosion, server-side uploads, and a tutor annotation editor are not implemented.

The shared viewer also provides smooth selected-mesh focus and previous-view return, per-asset camera save/restore in the current browser, adjustable global or selected-component mesh transparency, and an adjustable geometric clipping plane for GLB/glTF, OBJ, and STL surfaces. These are display operations on supplied geometry, not X-ray data. Clipping does not create caps or hidden/internal structures; transparency reveals only surfaces already present. The controls are disabled for atom-coordinate models and images when those operations would be misleading. No validated dragonfly model or compound-eye microscale asset is registered yet, so the dragonfly demonstration described in the requested roadmap remains unimplemented pending an authorized source model and review of its internal anatomy.

The seeded biological structure is experimentally determined crambin coordinates in RCSB PDB 1CRN. Its registry status `source_verified` means source provenance and notes were checked; it does not claim anatomical validation. The official RCSB archive data policy states PDB data are CC0 1.0 and encourages citation of original authors: [RCSB 1CRN](https://www.rcsb.org/structure/1CRN), [RCSB usage policy](https://www.rcsb.org/pages/usage-policy). The Physics Lab also contains a locally imported CC BY 4.0 static exploded-view image of the Roman Space Telescope Wide Field Instrument. The image is credited but has no interactive part hierarchy.

## Scientific sources

- **RCSB PDB:** the server proxies coordinate files from `files.rcsb.org`, validates PDB identifiers, caps response size, caches successful files for 24 hours, and attributes the source record. The endpoint does not copy structures into a second database.
- **PubChem:** the Chemistry Lab can open names/CIDs through PUG REST in the scientific viewer, which displays source properties and a PubChem 3D SDF conformer when one is available. Responses are cached for six hours and upstream calls are serialized to honor PubChem’s stated maximum of five requests per second. A missing conformer or unavailable service leaves an explanatory message. PubChem records can aggregate data with contributor-specific terms; the UI does not assert a single license for every record. See [PUG REST documentation](https://pubchem.ncbi.nlm.nih.gov/docs/pug-rest).
- **NOAA CO₂:** Graphing Lab can load monthly Mauna Loa atmospheric carbon dioxide observations from NOAA GML, with decimal-year coordinates, ppm units, source citation, and a note about the temporary 2022–2023 measurement-site change. The plot is an observed local-site time series, not a global CO₂ average. Data are cached for 24 hours; NOAA credits Scripps Institution of Oceanography for the pre-May 1974 measurements. See [NOAA trends data](https://gml.noaa.gov/ccgg/trends/data.html).
- **NIST constants:** Physics Lab links to the NIST CODATA 2022 reference table for physical constants. These are authoritative reference values, not measurements taken by the lab. See [NIST Fundamental Physical Constants](https://physics.nist.gov/cuu/Constants/index.html).
- **Elevation:** Geography Lab can query a 10×10 grid from ASTER GDEM v3 through Open Topo Data around the current map center. The source DEM is nominally about 30 m at the equator, but this rendered preview samples only 100 points across the selected map window; it is not a 30 m mesh. The API applies bilinear interpolation and can return missing samples. The route caps the window to 2 degrees, enforces a one-second upstream interval, and limits usage to 800 lookups per UTC day in process memory. Vertical exaggeration is a display setting and does not change the returned elevations in metres. Source notes and dataset date are displayed in the lab. See [ASTER dataset notes](https://www.opentopodata.org/datasets/aster/) and [Open Topo Data API](https://www.opentopodata.org/api/).
- Smithsonian Open Access requires an API key for the public API and item-level license checks. No key is embedded and no Smithsonian asset is imported. See [Smithsonian Open Access FAQ](https://www.si.edu/openaccess/faq).

External calls have bounded size/timeouts and user-facing fallback messages. Source-proxy endpoints require an authenticated session and have an additional per-IP request limit. CDN-based Three.js scripts need a browser connection; the viewer reports if those scripts fail to load.

## Calculations

`public/js/scientific-calculations.js` is shared by the labs and whiteboard. It covers common SI conversions, temperature conversion, molar concentration, uncertainty scaling, and fill-volume relationships. Cone and hemispherical fill volume use the vessel’s geometry rather than assuming a constant cross-section. Whiteboard layered liquids are an idealized immiscible stack sorted densest-first; mass uses the entered layer density, and supported cylindrical/prismatic overfill is reported. It does not model fluid mixing, viscosity, temperature, surface tension, or detailed vessel shape.

The Chemistry Lab uses `c = (mass / molar mass) / final volume`, with mass in grams, volume in litres, and molar mass in g/mol. This is a solution concentration calculation, not a chemical reaction or hazard prediction.

## Adding assets

1. Open **Scientific Assets** while signed in as a classroom tutor or administrator.
2. Submit a unique lower-case asset key, a supported model or data format, a source URL (HTTPS or an approved same-origin source route), the original source-record URL and identifier, institution, author, license, attribution, and scientific limitations.
3. New records remain `needs_review` and private. An administrator should check source metadata, record-specific terms, and scientific labels before publishing.
4. Use `source_verified` for checked provenance and recorded source terms only. Use `verified` only after a separate scientific review. These statuses do not certify clinical/anatomical validity or grant rights beyond the license recorded.
5. Use the classroom whiteboard **Insert sourced model reference** action. The whiteboard stores an editable reference card and asset key; double-clicking opens the real geometry in the viewer. Geometry is not flattened into the saved canvas. Typed asset links on lessons, materials, assignments, quizzes, or CBT exams are not implemented yet.

For API clients, the authenticated endpoints are `GET /api/science/assets?q=&subject=&format=`, `GET /api/science/assets/:assetKey`, `POST /api/science/assets` (tutor/admin), and `PUT /api/science/assets/:assetKey` (owner or admin; publication review is admin-only).

## Current scope and remaining work

This is a connected asset increment, not completion of every requested model feature. Biology's RCSB structure and Chemistry's PubChem compound conformer use source coordinates where available; procedural Chemistry workbench geometry remains illustrative. The CS & ICT exploded hardware model remains procedural; its local photograph is a reference only and the Sketchfab download candidate is not imported. Physics includes a licensed static exploded-view image but no 3D instrument geometry. Graphing Lab includes NOAA observations, while user-entered equations remain mathematical functions rather than measurements. Geography uses real sampled terrain plus illustrative landform scenes; the sampled terrain is not a full-resolution mesh. The whiteboard stores editable asset references and opens supported models in a viewer page; it does not embed synchronized WebGL geometry. Assets are not yet attached as typed lesson/assignment/quiz/CBT objects, and no model-identification grading key is implemented. No cutaway may imply unseen structures. Additional licensed models, independently validated cross-sections, and part-removal/exploded 3D assemblies require item-specific sourcing and technical review.

## Verification

Run the focused local tests with `npm run test:scientific-assets`. They cover unit conversions, liquid geometry, concentration, uncertainty, PDB/SDF parsing, asset access permissions, and mocked PubChem/ASTER proxy responses. The existing lab integration scripts connect to the configured MySQL database and should only be run against a disposable test database.
