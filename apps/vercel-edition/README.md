# Vercel Edition (initial adapter)

## Status

This edition routes the existing Express application through a Vercel Node.js
Function. It reuses the repository's existing UI, MySQL models, route
authorization, and session-based authentication; those are not Firebase
dependencies. Profile photos use Vercel Blob when running in this edition.
This is an incremental Vercel adapter, **not yet a fully serverless feature
parity release**.

The Vercel function is [api/index.js](./api/index.js). Vercel project root
must remain the repository root because the shared application, dependencies,
views, and public assets remain there. Root [vercel.json](../../vercel.json)
routes requests to the adapter and includes the required shared files.

## Provisioning

Create a separate Vercel project and a dedicated remotely reachable MySQL
database for this deployment. Apply the existing MySQL schema/migrations to
that database only after taking a backup and following
[database migration guidance](../../docs/deployment/database-migrations.md).
The app's MySQL-backed session store uses the shared `sessions` schema in
`schema.sql`; apply that schema and the existing application migrations to
the Vercel database before enabling login. Create a Vercel Blob store for
profile photos. This edition does not use
Firebase Authentication, Firestore, Cloud Functions, or Firebase Storage.

Configure the variables in [.env.example](./.env.example) as server-side
Vercel project variables. `SESSION_SECRET`, `DB_HOST`, `DB_NAME`, `DB_USER`,
`DB_PASSWORD`, and `BLOB_READ_WRITE_TOKEN` are required for production use.
Never use `.env.example` values as credentials.

Set the Vercel project's Node.js runtime to version 20 or newer for the
Vercel Blob SDK.
The existing application itself continues to support Node.js 18 when run
outside this edition.

## Local commands

At the repository root:

```powershell
npm install
npm run dev:vercel
npm run test:vercel
npm run build:vercel
```

`vercel dev` requires the Vercel CLI and a linked project or local environment
variables. Tests for chemistry, scientific assets, auth sessions, and session
security run without cloud credentials. Full API integration requires a
disposable MySQL database; Blob upload integration requires a Blob token.

## Deploy

Link the repository root to the Vercel project, set production variables,
provision the database and Blob store, apply reviewed schema migrations, then
run:

```powershell
npm run deploy:vercel
```

No deployment was made as part of this repository change.

## Known gaps before production parity

- Socket.IO realtime is not started in the serverless function. LiveKit
  tokens may be generated by APIs, but realtime classrooms/whiteboard require
  a separately validated realtime service path.
- The computer-science execution sandbox and any local filesystem consumers
  need explicit serverless runtime tests and may require an external runner.
- The Vercel CLI/build configuration has not been validated against a linked
  Vercel account, deployment, or provisioned MySQL/Blob resources.
- Firestore/Firebase Auth adapters are not included here; Firebase is a
  separate not-yet-implemented target.
